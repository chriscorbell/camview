# The Desk display watches through the Relay, not straight from the Camera

The **Desk display** sits on the same LAN as the **Camera**, so pulling RTSP from the **Camera** directly looks like the obvious low-latency path. We route it through the **Relay** instead. The **Camera** allows only two **Main stream** sessions and Frigate already holds one, so a 24/7 viewer can't take the other. The **Relay** forwards packets without buffering, so the extra hop costs next to nothing. Off-the-shelf Android RTSP players were never an option either: Media3 ExoPlayer still lands around 2–3 s even with minimal buffers, and its maintainers say it isn't built for real-time viewing ([androidx/media#1179](https://github.com/androidx/media/issues/1179)). How the **Desk display** plays the feed is covered in [0002](0002-desk-display-has-a-native-player.md).
