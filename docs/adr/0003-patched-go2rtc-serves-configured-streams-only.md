# The Relay runs a patched go2rtc that plays only its configured streams

The **Desk display** reads its stream from go2rtc's `/api/stream.mp4`. Upstream, that endpoint also creates a stream from any `?src=` URL, and with `?name=` it re-points an existing stream, including the **Camera**'s, until the next restart. The **Relay** has no login by design, so anyone on the LAN or tailnet could add sources or swap the picture every **Viewer** sees. go2rtc has no setting to turn this off, and there is no fix upstream as of v1.9.14. The other options were weaker: a login breaks the no-login decision; go2rtc's RTSP server lets anyone publish into an existing stream and would need an RTP depacketizer in the app; a filtering proxy adds a second process. So the image builds go2rtc from its pinned release with a five-line patch (`relay/serve-configured-streams-only.patch`) that makes every HTTP and WebSocket stream endpoint serve only streams named in the config. The runtime is still go2rtc alone. The cost is re-checking the patch whenever go2rtc is upgraded, and the CI smoke test fails if the protection goes missing.
