# Rebuild camview from scratch

Status: active
Objective: replace the old nginx + React + shell-script camview with a go2rtc-only Relay, a plain-TypeScript web viewer, and a native Android app for the Desk display.
Close when: the Relay and web viewer run on minicore, the Desk display runs the native app from a GitHub release and self-updates, and the Camera tweaks have been measured.

## Decisions (agreed with Chris, 2026-09-27)

These come from a design interview. The durable ones are in [ADR 0001](../../adr/0001-desk-display-watches-through-the-relay.md), [ADR 0002](../../adr/0002-desk-display-has-a-native-player.md), and the [glossary](../../../CONTEXT.md).

- One Camera, live video and audio only. No talkback, PTZ, snapshots, or recordings.
- **Relay**: go2rtc alone in the container, locked to `/` and `/api/webrtc`. It pulls Frigate's restream (`front_door`, `front_door_sub`), never the Camera directly. There is no login; it's reachable on the LAN and over Tailscale only.
- **Browsers** (Helium on the Mac, Safari on iOS) get the Main stream as 4K H.265 passthrough over WebRTC. Viewers without H.265 fall back to the Sub stream. Audio is converted from AAC to Opus. It stays 4K always, with no quality toggle.
- **Web UI**: video only with black bars. It starts muted, and the choice is remembered per device. Controls fade out. On a drop, the last frame stays up, dimmed, labeled "Reconnecting". A background tab stops pulling video.
- **Desk display**: a native Kotlin app registered as the tablet's home screen (the tablet has no other use). It hands video straight to MediaCodec and a SurfaceView at a steady 25 fps, with a buffer just big enough for the Keyframe stall. It plays the Camera's AAC audio as-is, has the same mute and reconnect behavior as the web UI, and self-updates from GitHub Releases (silent on Android 12+ after the first install). The tablet can't decode 4K, so it gets the Main stream converted to 1080p on minicore's GPU (VAAPI, radeonsi).
- **Camera**: fixed frame rate is ON (Chris set it; verified `constantFrameRate=1`). An I-frame interval of 1x is pending: Chris sets it in the Reolink desktop Client under Camera Settings → Device → Stream → Settings → Interframe Space. Then measure the stall before and after, and compare Frigate clips. Keep H.265.
- Delivery: Relay and web first (branch `rebuild-relay-and-web-viewer`), then the Android app on its own branch.
- Chris approved editing `/home/chris/docker/stacks/camview/compose.yaml` and the env file on minicore at cutover, and creating an app-signing key as GitHub secrets plus publishing releases.

## Cutover procedure

Watchtower recreates a container from the running container's config, not from the compose file. So first add the new env vars (`MAIN_STREAM_URL`, `SUB_STREAM_URL`, `LAN_ADDRESS`, `TAILSCALE_ADDRESS`) to minicore's compose and `docker compose up -d` while the old image still runs. Then merge and let Watchtower swap in the new image. Finally drop the old `env_file` and its variables.

## Verified so far

- A local run on agent-pc against Frigate's restream works. Headless Chrome (no H.265) fell back to the Sub stream: live in about 0.9–3 s, Opus audio arriving. Headful Chrome with VA-API got 4K H.265 at 24 fps, live in 1.7 s, with a video jitter buffer of about 0.2–0.3 s (the Keyframe stall).
- An outage is detected in about 2.7 s, the frozen dimmed frame and "Reconnecting" label show, and it's live again about 2.8 s after the Relay returns.
- The test scripts (puppeteer-core) are in `/tmp/camview-e2e` on agent-pc (temporary).
